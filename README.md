# AURA — музыкальное приложение

Веб-приложение (работает в браузере на телефоне и компьютере, можно «установить» на экран «Домой») для поиска, прослушивания и организации музыки из нескольких легальных источников, с приоритетом SoundCloud.

## Быстрый старт

Нужен [Node.js](https://nodejs.org) версии 20 или новее.

```bash
cd aura
npm install
npm run dev
```

Откройте http://localhost:5173. Сразу работают Audius, превью Apple, ваши файлы и воспроизведение ссылок SoundCloud. Для поиска по SoundCloud и аккаунтов нужны ключи (см. ниже).

Продакшн: `npm run build`, затем `npm start` (сервер отдаёт и сайт, и API на порту из `PORT`, по умолчанию 8787).

## Приложение для macOS и Windows

Десктопная версия сделана на **Electron**: внутри то же приложение плюс встроенный локальный сервер (слушает только `127.0.0.1:47831`, запросы с чужих доменов отклоняются).

Готовые файлы лежат в `release/`:

| Система | Файл |
|---|---|
| Mac с Apple Silicon (M1–M4) | `AURA-0.1.2-mac-arm64.dmg` |
| Mac с Intel | `AURA-0.1.2-mac-x64.dmg` |
| Windows 10/11 (64-бит) | `AURA-0.1.2-win-x64.exe` (установщик) |

**Первый запуск.** Приложение не подписано сертификатом разработчика Apple или Microsoft, поэтому система предупредит:
- **macOS:** откройте `.dmg`, перетащите AURA в «Программы». При первом запуске нажмите на значке правой кнопкой → «Открыть» → «Открыть». Если macOS пишет «повреждено», выполните `xattr -cr /Applications/AURA.app`.
- **Windows:** в окне SmartScreen нажмите «Подробнее» → «Выполнить в любом случае».

Чтобы предупреждений не было, нужна подпись: Apple Developer Program ($99 в год) с нотаризацией и сертификат подписи кода для Windows. electron-builder подхватит их через переменные `CSC_LINK` и `CSC_KEY_PASSWORD`.

**Особенности десктопной версии:**
- на macOS закрытие окна не останавливает музыку: приложение остаётся в Dock, полный выход — ⌘Q;
- работают медиаклавиши клавиатуры и системный виджет «Сейчас играет»;
- ссылки «Открыть оригинал» открываются в обычном браузере;
- данные (плейлисты, лайки) хранятся отдельно от браузерной версии.

**Ключи SoundCloud в десктопной версии:** меню «Справка → Папка настроек» откроет папку данных приложения. Положите туда файл `.env` со строками `SOUNDCLOUD_CLIENT_ID=…` и `SOUNDCLOUD_CLIENT_SECRET=…` и перезапустите AURA. Ключи Supabase (`VITE_…`) встраиваются при сборке: укажите их в `aura/.env` до запуска команд сборки.

**Пересобрать самому:**
```bash
npm run desktop     # запустить десктопную версию без упаковки
npm run dist:mac    # .dmg для Apple Silicon и Intel → release/
npm run dist:win    # установщик .exe для Windows → release/
```
Установщик Windows собирается и на Mac. Проверять его лучше на настоящем Windows.

## Источники музыки: что реально доступно

| Источник | Ключи | Что работает |
|---|---|---|
| **SoundCloud, режим ссылок** | не нужны | Вставьте в поиск или на главной ссылку на **артиста, плейлист/альбом или трек**. Список треков AURA берёт из официального встроенного плеера (Widget API `getSounds`), название и обложку — из oEmbed. Всё играет **полностью** через официальный плеер. На артистов можно подписаться: они появятся на главной и в библиотеке. Ограничения виджета: поиска по названию нет, лайки пользователя он не отдаёт, у артиста видна только первая порция треков. |
| **SoundCloud, режим API** | `SOUNDCLOUD_CLIENT_ID` + `SOUNDCLOUD_CLIENT_SECRET` на сервере | Поиск треков, исполнителей и плейлистов/сетов, страницы артистов, похожие треки, потоковое воспроизведение через подписанные ссылки. Если поток недоступен по правам, трек играет через виджет или ведёт на оригинал. |
| **Audius** | не нужны | Открытая платформа независимых артистов: полные треки, андеграунд, ремиксы, DJ-миксы, тренды, жанры, альбомы, плейлисты. |
| **Apple · превью** | не нужны | Мейнстрим-каталог (iTunes Search API): метаданные и **только 30-секундные превью**, помечены «30s». Полные треки Apple без подписки Apple Music недоступны. |
| **Мои файлы** | не нужны | MP3/M4A/WAV/FLAC/OGG с устройства. Хранятся в браузере (IndexedDB), никуда не загружаются. |

Честно о каталоге: приложение **не содержит «всю музыку мира»**. Охват равен сумме перечисленных источников. Аудио не скачивается, DRM и ограничения платформ не обходятся. Трек, который нельзя воспроизвести, показывается с пометкой и ссылкой на оригинал.

**Чего у SoundCloud нет в официальном API:** чартов (trending). Поэтому блок «Trending on SoundCloud» на главной это объясняет и не показывает выдуманных данных. Тренды берутся из Audius и подписаны.

## Почему некоторые треки играют только 30 секунд

Это превью Apple с пометкой **30s**: Apple законно отдаёт только 30-секундные отрывки. Мейнстрим-артистов (например, русский рэп) на Audius часто нет, поэтому в поиске остаются только превью. Что сделано:
- в поиске полные треки всегда стоят выше превью;
- если результатов-превью большинство, появляется подсказка и кнопка «Найти на SoundCloud»;
- у каждого превью в меню «⋯» и в плеере есть «Полная версия на SoundCloud». Найдите артиста, скопируйте ссылку на его профиль и вставьте в поиск AURA, и все его треки сыграют целиком.

## Подключение SoundCloud API

> ⚠️ Создать приложение SoundCloud теперь можно только с платной подпиской **Artist Pro**. Кроме того, по условиям SoundCloud публичный API в целом нельзя использовать в коммерческих целях, а в AURA есть платная подписка. Режим ссылок выше работает без этого.

1. Войдите на SoundCloud и откройте https://soundcloud.com/you/apps. Зарегистрируйте приложение. SoundCloud периодически закрывает приём новых заявок; если форма недоступна, остаётся режим ссылок.
2. Скопируйте **Client ID** и **Client Secret**.
3. В папке `aura` скопируйте `.env.example` в `.env` и заполните:
   ```
   SOUNDCLOUD_CLIENT_ID=ваш_id
   SOUNDCLOUD_CLIENT_SECRET=ваш_secret
   ```
4. Перезапустите `npm run dev`. В «Настройки → Источники» у SoundCloud появится зелёная галочка.

Как это устроено и почему безопасно: секрет хранится **только на сервере** (`server/soundcloud.ts`). Сервер получает токен по OAuth 2.1 Client Credentials, кэширует его примерно на час (SoundCloud ограничивает частоту выдачи токенов), обновляет при ответе 401, кэширует ответы на 5 минут и ограничивает частоту запросов с одного IP. Браузер получает только короткоживущие подписанные ссылки на поток. Соблюдайте [условия API SoundCloud](https://developers.soundcloud.com/docs/api/terms-of-use): указывайте авторство и ссылку на оригинал (в приложении это сделано).

> Точные лимиты и условия SoundCloud меняются. Сверяйтесь с https://developers.soundcloud.com/docs/api/guide. Если что-то не совпадёт, правка понадобится только в `server/soundcloud.ts` и `src/providers/soundcloud.ts`.

## Supabase: аккаунты и синхронизация

Без Supabase приложение работает в **локальном режиме**: плейлисты, лайки, история и профиль сохраняются в браузере и переживают перезагрузку. С Supabase появляются регистрация, вход, выход, восстановление пароля и синхронизация между устройствами.

1. Создайте бесплатный проект на https://supabase.com.
2. Откройте **SQL Editor**, вставьте содержимое `supabase/schema.sql` и нажмите **Run**. Будут созданы таблицы и правила доступа (RLS): каждый пользователь видит только свои данные, публичные плейлисты доступны для чтения всем.
3. **Project Settings → API**: скопируйте `Project URL` и ключ `anon public` в `.env`:
   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJ...
   ```
   `anon`-ключ публичный по замыслу Supabase, данные защищают политики RLS. **Никогда** не вставляйте в `.env` с префиксом `VITE_` ключ `service_role`.
4. **Authentication → URL Configuration**: добавьте адрес сайта (например, `http://localhost:5173`) в Site URL / Redirect URLs. Без этого не сработают ссылки из писем.
5. Перезапустите `npm run dev`. В «Профиль» появятся вход и регистрация.

**Регистрация:** логин (уникальный, вида `@логин`), имя, email и пароль от 8 символов. Логин проверяется на занятость до отправки формы, а триггер в базе создаёт профиль вместе с аккаунтом. Вход выполняется по email и паролю (email нужен Supabase для входа и восстановления пароля). Пароли хранит и хэширует Supabase, AURA их не видит.

> Если `schema.sql` уже запускался раньше, выполните ещё раз только новые блоки, начиная с «Registration» (повторный запуск целиком упадёт на уже созданных политиках).

## Аура: бесконечные потоки

- **Моя аура** — большая анимированная сфера на главной. Нажмите, и начнётся бесконечный поток под ваш вкус. Настройки:
  - *Характер:* «Любимое» (больше ваших артистов и иногда ваши лайки), «Незнакомое» (новые имена и андеграунд), «Популярное» (тренды недели);
  - *Настроение:* «Бодрое», «Спокойное», «Грустное». Работает по тегам настроения и темпу (BPM), которые даёт источник.
- **Аура трека** — бесконечный поток похожих треков. Запускается из меню «⋯» любого трека или кнопкой в полноэкранном плеере. Похожесть складывается из жанра, настроения, темпа (±8 BPM), похожих треков от источника и той же сцены.

**Как поток учится** (`src/recommend/aura.ts`, правила видны в коде):
- лайк поднимает вес артиста и жанра;
- пропуск в первые 30 секунд немного их снижает;
- «Не нравится» сильно снижает вес, пропускает трек и больше никогда его не покажет.

Очередь дополняется сама, когда впереди остаётся меньше трёх треков. В потоке не больше одного трека подряд от одного артиста, недавно прослушанное не повторяется, а длинные сеты в радио не попадают. Если ключи SoundCloud подключены, в поток добавляются и треки SoundCloud.

## Подписка AURA Premium

| Тариф | Цена | В месяц |
|---|---|---|
| 1 месяц | 300 ₽ | 300 ₽ |
| 6 месяцев | 800 ₽ | ≈133 ₽ (−56%) |
| 12 месяцев | 1200 ₽ | 100 ₽ (−67%) |

**Что даёт Premium:** безлимитные плейлисты (бесплатно — до 5), Daily Mix, визуализатор, загрузку своих аудиофайлов. **Слушать музыку можно бесплатно.** Premium продаёт функции приложения, а не доступ к чужой музыке: условия SoundCloud и Audius запрещают брать плату за доступ к их контенту.

Каждая покупка — разовый платёж без автопродления. Повторная оплата продлевает подписку от даты окончания текущей.

### Как устроена оплата
1. Пользователь выбирает тариф → сервер (`server/billing.ts`) проверяет его вход, берёт цену из своего списка (подделать цену из браузера нельзя) и создаёт платёж в **ЮKassa**.
2. Оплата идёт на защищённой странице ЮKassa (карта, СБП). Данные карты AURA не получает.
3. ЮKassa присылает уведомление на `/api/billing/webhook`, и одновременно приложение после возврата спрашивает `/api/billing/confirm`. В обоих случаях сервер **заново запрашивает платёж у ЮKassa** и не доверяет присланным данным. Подписка продлевается ровно один раз, даже если уведомление пришло повторно.
4. Подписки и платежи хранятся в таблицах `subscriptions` и `payments`. Изменять их может только сервер, пользователь — только читать свои.

### Как подключить
1. Подключите Supabase (раздел выше) и выполните обновлённый `supabase/schema.sql`.
2. Зарегистрируйте магазин на https://yookassa.ru (нужны ИП/самозанятый/ООО). Для проверки создайте **тестовый магазин**: его ключ начинается с `test_`, деньги не списываются, оплачивать можно тестовыми картами из документации ЮKassa.
3. Добавьте в `aura/.env` (только на сервере):
   ```
   SUPABASE_URL=https://xxxx.supabase.co
   SUPABASE_SERVICE_ROLE_KEY=...      # Supabase → Project Settings → API → service_role
   YOOKASSA_SHOP_ID=...
   YOOKASSA_SECRET_KEY=test_...
   PUBLIC_URL=https://ваш-домен       # куда вернуть пользователя после оплаты
   ```
4. В личном кабинете ЮKassa → **Интеграция → HTTP-уведомления** укажите `https://ваш-домен/api/billing/webhook` и событие `payment.succeeded` (и `payment.canceled`). Для локальной проверки уведомления не обязательны: статус подтверждается и при возврате в приложение.
5. Если в магазине включены онлайн-чеки (54-ФЗ), поставьте `YOOKASSA_RECEIPTS=true` и `YOOKASSA_VAT_CODE` (1 — без НДС).

**Десктоп-приложение** не должно содержать секретные ключи. Оплата работает через ваш развёрнутый сервер: при сборке укажите `VITE_BILLING_API_URL=https://ваш-домен`, а на сервере — `BILLING_CORS_ORIGINS=http://127.0.0.1:47831`. Страница оплаты откроется в браузере, а приложение дождётся подтверждения.

**Перед запуском продаж** опубликуйте публичную оферту, политику возврата и контакты поддержки (этого требует и ЮKassa) и добавьте ссылки на них на экран «Premium». Проверки Premium-функций в интерфейсе работают на стороне клиента: этого достаточно для удобства, но если какую-то функцию нужно защищать по-настоящему, её проверку надо перенести на сервер.

## Возможности

- **Плеер:** реальное HTML5-аудио (и hls.js для HLS-потоков) либо официальный виджет SoundCloud. Play/Pause, предыдущий/следующий, перемотка, прошедшее и оставшееся время, громкость (на iOS её задают только кнопки устройства, поэтому слайдер скрыт), перемешивание, повтор трека или очереди, очередь с перетаскиванием, «играть далее», «в очередь». Сломанный трек пропускается с сообщением. Очередь восстанавливается после перезагрузки.
- **Системная интеграция:** Media Session (экран блокировки, уведомление, медиаклавиши), фоновое воспроизведение там, где его разрешает браузер.
- **Горячие клавиши** (нажмите `?`): пробел, ←/→, Shift+←/→, ↑/↓, M, S, R, L, F, Q, `/` или ⌘K.
- **Экраны:** Главная, Поиск, Библиотека, Профиль, полноэкранный плеер, плейлист, исполнитель, альбом или плейлист источника, Daily Mix, очередь (`/queue` или кнопка), Настройки.
- **Поиск:** по всем источникам параллельно; категории (треки, исполнители, альбомы, плейлисты, ремиксы, DJ-сеты); фильтр по источнику, типу и жанру; подсказки; история с очисткой; жанровые подборки; вставка ссылки SoundCloud; состояния загрузки, пустого результата и ошибки для каждого источника отдельно.
- **Плейлисты:** создание, название, описание, обложка, приватный/публичный режим, добавление (меню, поиск внутри плейлиста, перетаскивание трека на плейлист в боковой панели), удаление с «Вернуть», перетаскивание для изменения порядка, сортировка, копия, удаление с подтверждением. Недоступные треки сохраняют метаданные и помечаются.
- **Библиотека:** плейлисты, любимые, альбомы, исполнители, недавние, сеты, мои файлы; поиск по библиотеке и сортировка.
- **Рекомендации (прозрачный алгоритм без ML, `src/recommend/engine.ts`):** вес жанров и артистов считается из лайков (×3), прослушиваний дольше 30 сек, треков в плейлистах (×2), подписок и выбора при онбординге (×4). Кандидаты берутся из реальных трендов Audius по вашим жанрам; уже знакомое убирается. Под каждой рекомендацией написана причина. Пока данных нет, приложение предлагает выбрать жанры, а не выдаёт случайное за персональное. Daily Mix меняется раз в сутки.
- **Дизайн:** чёрно-белая палитра (цвет от обложки включается в настройках), прозрачное Liquid Glass (размытие, блики, многослойность) на навигации, плеере, меню и модальных окнах; тёмная и светлая тема; цвет интерфейса плавно подстраивается под обложку; spring-анимации; разворачивание мини-плеера в полноэкранный; визуализатор по реальному спектру (Web Audio); учёт `prefers-reduced-motion` и режим «Меньше анимаций»; облегчённое стекло (включается автоматически на слабых устройствах).

## Структура

```
aura/
├── server/                  Node-сервер: SoundCloud-прокси (секреты), раздача сборки
│   ├── app.ts               общий сервер (веб и десктоп)
│   ├── index.ts             запуск для веба
│   └── soundcloud.ts
├── electron/                десктопная оболочка (main.ts, preload.ts)
├── build/icon.png           иконка приложения
├── supabase/schema.sql      таблицы и политики доступа
├── src/
│   ├── providers/           ЕДИНЫЙ интерфейс источников (types.ts) + реализации
│   │   ├── types.ts         MusicProvider, Track, Artist, Collection
│   │   ├── registry.ts      список источников, параллельный поиск
│   │   ├── soundcloud.ts  audius.ts  itunes.ts  local.ts
│   ├── player/              движки (HTML5 / виджет SC), контроллер, состояние, хоткеи
│   ├── store/               библиотека, настройки, UI (zustand + localStorage)
│   ├── auth/                Supabase Auth и синхронизация
│   ├── recommend/           алгоритм рекомендаций
│   ├── components/          дизайн-система (ui/), карточки, строки треков, навигация, плеер
│   ├── screens/             экраны
│   └── lib/                 сеть и кэш, цвет обложки, утилиты
```

**Как добавить новый источник** (например, Jamendo): создайте `src/providers/jamendo.ts`, реализуйте `MusicProvider` (минимум `search` и `resolveStream`), добавьте его в `providers` и `SOURCE_META` в `registry.ts` и id в тип `SourceId`. Поиск, плеер, плейлисты и библиотека подхватят его сами. Если API требует секрет, добавьте маршрут в `server/`, как сделано для SoundCloud.

## Технологии

React 18, TypeScript, Vite 6, Tailwind CSS 4, Motion (Framer Motion), Zustand, React Router, hls.js, idb-keyval, Supabase JS, lucide-react; сервер на Node без фреймворков (запуск через tsx).

**Почему веб-приложение, а не React Native.** Одна кодовая база работает на iOS, Android и десктопе, а Liquid Glass (`backdrop-filter`) и анимации на вебе получаются качественными. Нужен магазин приложений — оберните сборку в **Capacitor**: код менять почти не придётся, добавится нативный фоновый звук. React Native означал бы переписать интерфейс, и делать это стоит только ради глубоко нативных функций.
